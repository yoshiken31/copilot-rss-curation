# 選別基準

目的は「読む価値のある実践事例だけを、事前に選んで届ける」ことです。迷ったら厳しめに判定します。

## 対象の分野
1つの記事が複数にまたがる場合は、最大2つまで付けます。
- md: Copilot指示ファイル運用（カスタム指示、プロンプト設計、Copilot Studioのトピック設計など）
- token: コスト・効率管理（プレミアムリクエスト節約、モデル使い分け、応答品質の改善）
- app: Copilot Studio活用（カスタムエージェント、チャットボット構築、業務フロー自動化）
- dx: DX・業務改善（Microsoft 365 Copilot、Power Automate、Graph API連携、社内ツール化）

## 高く評価する特徴
- 具体的な数値がある（例：問い合わせ対応時間が50%削減）
- Before/Afterがある
- 手順・設定例がそのまま真似できる
- 日本の企業・現場での事例

## 点数の基準
- 5点: そのまま真似できる具体的な手順・設定例・数値があり、すぐ試せる
- 4点: 具体的な事例で、参考になる部分がはっきりある
- 3点: 参考にはなるが、具体性が弱い
- 2点以下: 採用しない

5点は全体の1割程度が目安です。点数が上に偏らないようにします。

## 採用しない記事
- 宣伝・製品紹介だけの記事
- ニュースの転載・発表まとめ
- 体験談だけで再現できる情報がない記事
- GitHub Copilot（コード補完）に関する記事
- Microsoft Copilot以外のAIツール紹介記事

## 好例
1. 「Copilot Studioで社内問い合わせボットを作ったら、対応件数が月200件から50件に減った」という記事。
   理由は、数値・結果・転用性の3つがそろっているためです。
2. 「Microsoft 365 CopilotをTeamsに導入した手順と、展開時の落とし穴まとめ」という記事。
   理由は、具体的な手順と実際に起きた問題が書かれており、そのまま参考にできるためです。
