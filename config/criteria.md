# 選別基準（自由に編集してください）

目的は「読む価値のあるGitHub Copilotの実践事例だけを、事前に選んで届ける」ことです。迷ったら厳しめに判定します。

## 対象の分野
1つの記事が複数にまたがる場合は、最大2つまで付けます。
- md: 指示ファイル運用（copilot-instructions.md、*.instructions.md、AGENTS.md、プロンプトファイル、カスタムエージェント、リポジトリ設計など）
- token: プレミアムリクエスト・コンテキスト節約（モデルの使い分け、コンテキスト管理、利用量・コストの削減など）
- app: アプリ開発（Copilot Agent mode、Coding Agent、Copilot CLI、VS Code拡張、MCPを使った開発事例）
- dx: DX業務自動化（業務の自動化、ワークフロー、GitHub Actions連携、社内ツール、Microsoft 365・Power Platform連携を含む）

## 高く評価する特徴
- 具体的な数値がある（例：レビュー時間が半分になった、プレミアムリクエスト消費が3割減った）
- 結果が確認できる（Before/Afterがある）
- 手順・設定ファイル・プロンプトの例が、そのまま真似できる
- 自分の環境や業務に転用できる

## 点数の基準
- 5点: そのまま真似できる具体的な手順・設定例・数値があり、すぐ試せる。
- 4点: 具体的な事例で、参考になる部分がはっきりある。
- 3点: 参考にはなるが、具体性が弱い。
- 2点以下: 採用しない。

5点は全体の1割程度が目安です。点数が上に偏らないようにします。

## セキュリティの話題
Copilot・MCP・AIエージェントの利用に直結するものだけ採用します。
- 採用する例: 拡張の権限・設定、プロンプトインジェクション対策、無人運用の安全対策
- 採用しない: 一般的なセキュリティ報道、他社AIの脆弱性、一般的なパッケージ管理の話題

## 採用しない記事
- 宣伝・製品紹介だけの記事
- ニュースの転載・リリースノートの翻訳だけの記事
- 体験論だけで、再現できる情報がない記事
- 技術的な学びがない雑談・趣味の話（Copilotを使った事例でも、他に転用できる手法が書かれていなければ除外）
- Copilotが主題でない記事（他のAIコーディングツールの話が中心のもの）

## 好例
1. 「copilot-instructions.mdを整理して、レビュー指摘の手戻りが減った」という記事。
   理由は、数値（手戻りの減少）・結果（Before/After）・転用性（自分のリポジトリにも使える）の3つがそろっているためです。
2. 「Copilot Coding AgentにIssueを任せるGitHub Actions構成」という記事。
   理由は、具体的な設計（権限、レビュー前の検査）と、そのまま使える雛形があり、実際に動いている例だからです。
